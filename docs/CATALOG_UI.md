# Каталог приложения — 02.10.2026

## Разделы

Светлый список по предоставленному образцу: строка не ниже 64 logical px, миниатюра 48×48, название 15 px semibold, стрелка и тонкий разделитель. Длинные названия переносятся; при крупном шрифте строка растёт. Порядок, изображения и названия берутся из API, чужие категории не добавляются. Закреплённый поиск открывает существующий поиск. Меню, избранное и сравнение остаются доступны сверху.

## Подразделы

«Смотреть все» и раскрывающиеся группы с изображением; внутри — «Смотреть все модели» и серии, как в референсе. Обратный переход из серии возвращает к списку групп, следующий — к корневым категориям. Поиск доступен справа от заголовка.

`get_categories.php` отдаёт только верхний уровень. Иерархия взята из фактического публичного меню сайта 02.10.2026: `lib/data/catalog_navigation.dart`, 11 корневых кодов / 21 группа. Это снимок названий и URL, не новый серверный API. Генератор `tools/update_catalog_navigation.py` обновляет его из `/catalog/` без записи на сервер. URL из подробностей товара определяет принадлежность SKU. Пустые группы/серии скрываются по текущим данным API; для раздела без групп сразу открываются товары. У смартфонов реально есть iPhone, Samsung и Google Pixel; чужие бренды не добавляются. Новые группы сайта потребуют обновления снимка и приложения; смотреть все товары можно и до обновления.

## Товары

Две колонки, общий с главной `ProductPreviewCard`: отдельная строка значков над фото (RuStore, избранное и сравнение), изображение, цена сайта перед названием, название до трёх строк, цена магазина при наличии, кнопка покупки с белой подписью. Недоступный или бесценовой SKU открывается через «Под заказ», а не добавляется с ценой модели. На главной значки также вынесены в строку над фото: высота самой фотографии сохранена, информационная часть остаётся компактной. Последний одиночный товар располагается слева. В корзину передаётся конкретный вариант и его цена. Сохранённые товары сохраняют SKU, наличие, обе цены и код характеристики.

Компактная строка сортировки/фильтров и горизонтальные плашки быстрых параметров. Полная панель перекрывает нижнюю навигацию, её заголовок по центру, цена с двумя полями и RangeSlider; характеристики — FilterChip в Wrap, до шести значений сразу, остальные по «Все». Быстрая плашка открывает выбор одного параметра. Цена сайта «От / До», только подтверждённое наличие и все различающиеся характеристики, переданные API. Несколько значений одного свойства работают через «или», разные свойства — через «и». Код свойства и источник (модель / вариант) образуют ключ: одинаковые названия разных свойств не объединяются. Отсутствующие характеристики не угадываются по названию. В панели есть сброс, предварительный счётчик и проверка диапазона цен. Закрытие без применения сохраняет прежний результат. Нулевой результат содержит сброс. Внутри модели доступные варианты с ценой идут перед остальными; модели сохраняют серверный порядок. Сортировка: исходный порядок, сначала дешевле / дороже, название; товары без цены идут последними при сортировке по возрастанию.

## Данные и ограничения

Текущий `get_products.php` поддерживает только раздел, тип и страницы — серверных фильтров у мобильного API нет. `getCatalogItems` сначала читает все страницы раздела по 50 моделей, затем подробности пакетами до четырёх одновременных запросов. Все активные SKU разворачиваются в отдельные карточки; счётчик означает варианты, а не родительские модели. Показ по 20 карточек ограничивает отрисовку, фильтрация и сортировка учитывают весь загруженный раздел.

Во время загрузки фильтры недоступны. Ошибка любой части не выдаёт неполный набор за полный раздел; есть повтор. Смена раздела/возврат отменяет публикацию старого результата и прекращает запуск следующих пакетов. Уже отправленные HTTP-запросы завершаются. Первая загрузка длиннее прежней: нужны подробности всех моделей. Серверная фасетная выдача остаётся возможным улучшением производительности.

Набор фильтров соответствует данным мобильного API, а не гарантированно всем настройкам Bitrix smart.filter на сайте. API не отдаёт ID/порядок/параметры видимости серверных фильтров. Сайт и сервер в этой задаче не изменялись.
