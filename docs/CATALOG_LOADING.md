# Загрузка каталога — 02.10.2026

Следующее изменение подготовлено локально: ApiService запрашивает `get_catalog.php` по восемь моделей и получает готовые SKU с компактными характеристиками. Для 63 моделей контракт предусматривает восемь запросов вместо 65. Обработчик ещё не опубликован; при 404 приложение использует прежнюю схему и запоминает отсутствие нового API. Иные ошибки показываются пользователю. Общее время/трафик после публикации пока не измерены.

Кандидат сервера и план живой приёмки: `H:/Codex/Replatinum_sait/docs/site/mobile-compact-catalog-api-20261002.md`. 72 Flutter-теста прошли после подключения клиента; четыре локальных PHP mock-проверки и синтаксическая проверка обработчика прошли. На реальном Bitrix и телефоне новый API ещё не проверен. Старые замеры ниже относятся к схеме с подробностями каждой модели.

## Причина задержки

Раньше экран ждал все страницы моделей и подробности каждой модели, чтобы сформировать полный набор SKU и фильтров. В смартфонах живой API вернул 63 модели / 339 вариантов: 2 запроса списка + 63 запроса подробностей. Поле описания и прочие подробности увеличивают ответы, хотя для списка большая часть этих данных не нужна. Отдельный проверенный ответ модели 1596 — около 1 МБ.

Read-only замер с компьютера через настоящий Dio/ApiService: 65 запросов, 8 943 175 байт повторно сериализованного JSON (не размер HTTP-трафика, без фотографий). До изменения публикации данных весь экран ждал завершения: в двух прогонах 10 356 и 11 531 мс. Это текущие сетевые прогоны, а не измерение на физическом телефоне или сравнение двух release APK.

## Локальное изменение

- Известные подразделы из снимка публичного меню доступны сразу. До завершения загрузки пустые ветки ещё не определены; после загрузки они скрываются по фактическим SKU. Отсутствующая миниатюра заменяется значком.
- Каждая страница моделей обрабатывается сразу: подробности идут пакетами по четыре запроса, подтверждённые SKU публикуются после каждого пакета. Не требуется ждать следующую страницу или весь раздел. В живом прогоне первые 49 вариантов доступны на 3 844 мс при полной загрузке 11 531 мс. В предыдущем прогоне — 3 861 / 10 356 мс.
- Во время догрузки виден индикатор и подпись «Загружено», количество не выдаётся за окончательный итог. Фильтры и сортировка открываются только после получения полного раздела. Карточки уже можно открывать.
- Полностью загруженный раздел сохраняется в памяти ProductProvider на две минуты; не более четырёх разделов, ключ включает section_id и type. Возврат в свежий раздел не делает HTTP-запросов. Перезапуск приложения очищает этот кэш. Кнопка «Обновить товары» принудительно получает свежие данные. Цена/наличие в снимке могут отставать до двух минут; карточка товара заново запрашивает подробности, оформление использует серверный расчёт корзины.
- Неполный результат при ошибке убирается и не кэшируется; повтор запрашивает раздел заново. Устаревшие результаты после смены раздела/возврата игнорируются, следующие пакеты не запускаются; отправленные запросы завершаются.

Общий объём JSON при первом открытии пока прежний. Следующее основное ускорение требует отдельной задачи на сервере: компактная выдача SKU, URL раздела и фасетов с пагинацией/серверной фильтрацией вместо N запросов подробностей. Полные описания нужны при открытии карточки. API/сайт в этой задаче не изменялись.

## Проверки и воспроизведение

Использованы Flutter Best Practices, Flutter Pre-caching и Testing; данные предзагружаются только для текущего раздела. Рекомендации по разделению данных и UI сверены с официальной документацией Flutter: https://docs.flutter.dev/app-architecture/design-patterns/offline-first .

`tools/probe_catalog_loading.dart` выполняет только публичные GET: `D:\flutter\bin\dart.bat --packages=.dart_tool/package_config.json tools/probe_catalog_loading.dart`. Считает время до первой порции, до завершения, число запросов и размер повторно сериализованного JSON.

67 тестов прошли до удаления верхнего значка корзины; анализатор без замечаний. Новые проверки: публикация SKU до последних ответов, отсутствие неполных фасетов, поздняя ошибка/повтор, кэш/принудительное обновление/истечение срока, переходы и отменённый результат, видимость навигации и карточек при догрузке. Существующие проверки 320/360/600 logical px и большого шрифта проходят. Эмулятор в момент проверки не подключён; физический телефон и новый release APK не проверены.

Все изменения локальные. По указанию пользователя в GitHub не отправлять до завершения последующих правок.
